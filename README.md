# ForeSight 3.0

Machine learning and graphical analysis for **cryptocurrency forecasting** — the bridge between
doctoral research in forecasting and time series and real portfolio operation.

The project owns its full stack: its own **database**, its own **forecasting systems**, and its
own **simulation systems**.

---

## Seven strategies tested. Six dead. One survives.

That headline is the point of this repository. Most published crypto research shows the backtest
that worked. This one shows all of them, including the six that did not, because a method that
never kills its own ideas has not been tested.

| tested | verdict | evidence |
|---|---|---|
| Minute-scale direction from price | **DEAD** | R² −1.02 vs predicting zero, 49.4% hit rate |
| Classic chart indicators (38 of them) | **DEAD** | 1 survives multiple-testing correction, and points the wrong way |
| GARCH / GJR-GARCH / EGARCH | **BEATEN** | all three fall *below* the naive carry-forward |
| Our vol model vs the options market | **LOST** | Deribit DVOL RMSE 0.227 vs our 0.311 |
| Variance risk premium after costs | **BREAKEVEN** | breakeven at ~1.5 vol points round-trip |
| Funding carry (long spot / short perp) | **ARBITRAGED** | 30.6% in 2021 → 3.4% trailing twelve months |
| Positioning data (OI, top-trader ratios) | **DEAD** | 0 of 16 features survive correction |
| **Trend following + vol-scaled sizing** | **SURVIVES** | beats buy-and-hold on BTC *and* ETH |

### The one that survived

Long when the trailing return is positive, sized inversely to recent volatility, otherwise flat.
Daily bars, 10 bps costs. **The full parameter grid, not its best cell:**

| lookback | BTC Sharpe | ETH Sharpe | BTC max drawdown |
|---|---|---|---|
| 30d | **0.99** | **0.81** | 0.54 |
| 60d | 0.92 | 0.73 | 0.72 |
| 90d | 0.61 | 0.49 | 0.71 |
| 180d | 0.59 | 0.31 | 0.73 |
| 365d | 0.61 | 0.40 | 0.66 |
| *buy & hold* | *0.45* | *0.25* | *1.15* |

The ETH replication is what makes it credible: the rank ordering across lookbacks is nearly
identical on two independent assets. A pattern that exists only on Bitcoin is a Bitcoin fact, not
a method. The value is concentrated in **downside protection** — drawdowns roughly halved, and
through 2021–22 every variant lost less than holding.

### ⚠ The finding that cost the most to learn

**A better forecast is a worse position sizer.**

| sizing | momentum Sharpe | turnover/yr |
|---|---|---|
| simple 20-day realized vol | **0.61** | 7× |
| our LightGBM vol forecast | 0.50 | 48× |

The LightGBM model beats HAR by 30% on forecast accuracy and still loses as a sizer, at 7× the
turnover. Forecasting rewards responsiveness; sizing rewards stability. No additional accuracy
fixes this.

### Honest limits on all of the above

- **Sharpe standard error is 0.35.** The trend margin over buy-and-hold is roughly 0.5–1.5 SE.
  Suggestive, not conclusive.
- Both assets rose enormously across the window, which flatters a long-biased rule.
- Trend following is a **crowded, documented risk premium**, not a discovery.
- A backtest without slippage, funding and execution risk is not a live result.
- The positioning sample starts 2023 (Binance retains those metrics files for a limited window).

Full detail: [`PHASE1-REPORT.md`](PHASE1-REPORT.md) and the nine script-generated result files in
[`forecasting/evaluation/`](forecasting/evaluation/).

## Method discipline

Every result above was produced under these rules, which are enforced in
[`CLAUDE.md`](CLAUDE.md) and visible in the code:

1. **Chronological splits only** — never a random split of a time series. Scalers, imputers and
   encoders fit on the training window alone.
2. **Walk-forward** — every block is scored before it is trained on.
3. **Costs charged everywhere.** A backtest that ignores costs is a fiction; the no-cost number is
   never reported alone.
4. **Multiple-testing correction** (Benjamini-Hochberg) when testing 38 indicators at once.
5. **The full parameter grid is reported**, not its best cell.
6. **Point-in-time correctness** is treated as the whole game; `tests/` exists primarily to catch
   leakage, and a leakage test is worth more than a unit test here.
7. **Provenance** — every source archive SHA-256 verified against the checksum published beside
   it; every reported number generated by a committed script, never typed into prose.

Two bugs produced believable *wrong* answers and were caught by the results being **implausible**,
not by a test failing. Both are recorded here rather than quietly fixed, because how a project
catches its own errors is part of what its numbers are worth:

- **A December-2017 "14-day outage"** that never happened. It was 20,400 real bars falling outside
  the expected minute grid. The tell was implausibility: that fortnight was the blow-off top and
  the most heavily traded stretch in Binance's early history, so an outage there made no sense.
  Full ruling and the reconciliation arithmetic in
  [`docs/DECISIONS.md`](docs/DECISIONS.md).
- **A forward-return leak.** The first momentum signal was built from the `cumsum` of *forward*
  returns, so the running total at *t* already contained the return being predicted — correlation
  exactly **1.000**. Rebuilt from trailing returns; the 12-month sign only flipped on 0.8% of days,
  so the conclusion survived, but it had to be **measured** rather than assumed.

## Layout

```
├── config/              Run configuration. NO secrets.
├── db/                  Schema, forward-only migrations, shared queries
├── data/                raw (immutable) → interim → processed; external reference data
├── ingestion/           Per-exchange collectors
├── features/            Feature engineering, one module per family
├── forecasting/         models · training · evaluation · backtesting
├── simulation/          engine · strategies · scenarios
├── analysis/            graphical · notebooks · reports
├── scripts/             Deterministic entry points: fetch, build, train, simulate, report
├── tests/               Especially leakage and point-in-time correctness tests
└── docs/                Design notes, data dictionary, decision log
```

## Setup

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env      # then set FORESIGHT_DATA_ROOT and any read-only API keys
```

Never commit `.env`. Exchange API keys, wallet keys and account identifiers belong there and
nowhere else; use read-only keys wherever the exchange offers them.

## Roadmap

What is built is above. What is not built is listed here, deliberately kept separate:

- **Live paper trading** — the real next step. The trend result needs contact with actual
  slippage far more than it needs another parameter sweep.
- Per-signal explainability (SHAP).
- Zero-shot / few-shot transfer learning to assets with little history.
- On-chain publication of signals via oracle, for an auditable and manipulation-resistant record.
- Automatic retraining on concept-drift detection.
